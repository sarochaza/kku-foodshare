# การกำหนดจุดรับด้วยลิงก์ Google Maps

## วิธีใช้ในหน้าสร้างและแก้ไขโพสต์

1. เปิด Google Maps แล้วค้นหาสถานที่ หรือแตะตำแหน่งจุดรับบนแผนที่
2. คัดลอก URL แบบเต็มจากแถบที่อยู่ของเบราว์เซอร์ แล้ววางในช่อง “วางลิงก์ตำแหน่งจาก Google Maps”
3. กด “ใช้ลิงก์นี้” และตรวจตำแหน่งหมุดบนแผนที่ก่อนเผยแพร่
4. ถ้าหมุดคลาดเคลื่อน ให้แตะจุดที่ถูกต้องบนแผนที่หรือลากหมุดเพื่อแก้ ระบบจะบันทึกพิกัดใหม่ลง `latitude` และ `longitude` เดิม

## URL ที่รองรับ

- URL เต็มที่มีพิกัดใน query เช่น `https://www.google.com/maps/search/?api=1&query=16.4796266%2C102.8140024`
- URL ของแผนที่ที่มี `@latitude,longitude,zoom` เช่น `https://www.google.com/maps/@16.4796266,102.8140024,16z`
- URL สถานที่ที่มีพิกัดหมุดใน `!3dlatitude!4dlongitude`

ค่า `@latitude,longitude` เป็นจุดกึ่งกลางแผนที่ จึงอาจไม่ใช่หมุดสถานที่ที่ผู้ใช้เลือก ระบบแสดงคำเตือนให้ตรวจตำแหน่งก่อนบันทึก ส่วนลิงก์ย่อ เช่น `share.google` และ `maps.app.goo.gl` ไม่มีพิกัดให้อ่านโดยตรงในหน้าเว็บ ให้เปิดลิงก์ในเบราว์เซอร์แล้วคัดลอก URL แบบเต็ม หรือเลือกจุดบนแผนที่แทน

ถ้า URL ไม่ใช่ Google Maps URL ที่รองรับ พิกัดไม่ครบ หรืออยู่นอกช่วง latitude/longitude ระบบจะแจ้งข้อผิดพลาดโดยไม่เปลี่ยนหมุดเดิม

## การคง Data Contract และเส้นทาง

ฟีเจอร์นี้ใช้ช่องข้อมูลโพสต์เดิม `pickupLocationName`, `latitude` และ `longitude` ไม่มีการเปลี่ยน database schema หรือ API สำหรับบันทึกโพสต์ เส้นทางของผู้จองยังคำนวณจากพิกัดต้นทางที่ยืนยันแล้วและพิกัดจุดรับของโพสต์

## Regression test

รัน JavaScript regression tests จากโฟลเดอร์โปรเจกต์หลัก:

```bash
node --test code/src/test/js/*.test.mjs
```

การทดสอบลิงก์อยู่ใน `code/src/test/js/place-picker.test.mjs` ครอบคลุม URL แบบ map-center, query, pin, ลิงก์ผิดโดเมน, พิกัดผิดช่วง, ลิงก์ย่อ และการคงหมุดเดิมเมื่ออ่านลิงก์ไม่ได้
