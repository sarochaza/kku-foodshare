# Data dictionary

Schema after Flyway V1–V10: 12 application tables; flyway_schema_history is framework metadata. SQL definitions below are derived from the cumulative migration scripts. PK implies NOT NULL. This document does not modify migrations.

## Relationships, fetch and cascade

- One-to-One: user_profile_images.user_id is PK/FK; notification_preferences.user_id is unique FK.
- One-to-Many: users → food_posts/reservations/comments; food_posts → reservations/images/comments. Entities map many of these from the child side with @ManyToOne(LAZY); an inverse collection is not required.
- SavedPost is an explicit association entity between users and food_posts with unique(user_id,post_id). It is not a JPA @ManyToMany field; do not claim an extra-credit award without instructor confirmation.
- Most related entities use LAZY. Services load data in transactions because open-in-view=false.
- Migrations do not declare automatic ON DELETE CASCADE; ORM associations also do not use blanket CascadeType.ALL. Close/cancel, disable accounts and soft-delete comments preserve history and avoid deleting reservations/audit records with a parent.
- V5 changes food_post_images from one image per post to a gallery. V9 adds parent and reply-target links to comments.
- V10 backfills old onboarding flags TRUE and sets the default for future accounts FALSE.
